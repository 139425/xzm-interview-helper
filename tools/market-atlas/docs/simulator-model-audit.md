# 股票教学模拟器：模型与对抗审查

核对日期：2026-10-02。范围：`lib/simulator.ts`、`components/simulator.tsx`、`tests/simulator.test.ts`。只模拟五只虚构普通主板股票，不接收真实市场的订单，也不将腾讯行情当作本地撮合依据。

## 已实现与交易规则依据

- **DAY 与跨日条件**：新限价默认 DAY，推进到下个模拟交易日前，将当天未成交余量标为到期，释放资金/股份。CONDITIONAL 将条件保存在模拟器，每日重新尝试；并非交易所 GTC 申报。深交所 2026 规则 3.3.21 明确当日申报有效、普通申报未成交部分继续参加当日竞价。
- **部分成交**：逐档消耗虚构对手量，记录已成交/剩余股数；限价余量继续冻结，撤单只撤余量。教学市价使用最优五档即时成交剩余撤销形式；深交所 3.3.4 对这一形式有明确描述。
- **价格/时间优先**：跨日重申报队列中，买价高、卖价低者优先，同价按提交顺序；仅比较本账户订单。依据深交所 3.4.2 和上交所 3.5.1。
- **普通主板基础规则**：买入 100 股或其整数倍、零股余额一次申报卖出、0.01 元最小价格单位、T+1 可卖、通常 10% 涨跌幅。数量申报规则不约束每一个部分成交片段。依据深交所 3.1.4、3.3.8–19。
- **方向涨跌停**：锁住涨停时没有卖盘的教学假设只限制买入，仍可卖给涨停买盘；跌停对应关系相反。无对手量时 IOC 的余量撤销，不收无成交费用。

来源：[深圳证券交易所交易规则（2026 年修订）全文](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)、[深交所发布通知](https://investor.szse.cn/lawrules/rule/trade/t20260424_620190.html)、[上海证券交易所交易规则（2026 年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。两所通知公布自 2026-07-06 起施行；网页部分状态标签仍显示“尚未施行”，以通知正文的施行日期为核对依据。模型没有声称实现全文全部制度。

## 教学市场如何工作

每只股票每个方向每日共享虚构成交量的 1% 预算，数量按 100 股粒度分配到五档。资金账户下所有订单共享预算；反复下单、卖出或撤单均不会刷新已经消耗的买入预算。真实盘口会实时补充和撤销，本模型每天只补充一次。

当前订单仅撮合当前快照，不能使用此前的日内最低价补造一笔早先成交。跨日条件订单使用新交易日 OHLC 检查是否可能触价，然后生成虚构触价深度撮合。日 K 不包含真实触价时刻、顺序与可用成交量，因而这仍是日级近似，不是交易所逐笔回放。成交记录保留各档的数量与价格，其 `price` 是成交金额除以数量的加权均价，可能多于两位小数；各档价格仍按 0.01 元递增。

佣金按同一订单同一模拟交易日合并，最低佣金不会按五档重复收五次；跨日条件重新申报在新的交易日重新计费。冻结现金包含余量按限价的价款与尚需费用。次日重申报需要补足新的最低佣金而余额不足时，原冻结与余量保留，该日不重申报并显示原因，允许撤销余量。

新情境：`gap` 每四日产生隔夜跳空；`illiquid` 将成交量缩至常规模型的约 1.5%；`suspension` 中青禾医疗在第 5–6 日因虚构重大事项停牌，第 7 日复牌并跳空。停牌沿用前一价格估值，但两侧无可成交深度，不能将账面资产当作可即时卖出的现金。

## 兼容与容量

旧状态无需重新创建账户。没有新增字段的旧挂单继续解释为跨日条件；开放订单的原现金、成本、已记录成交和初始冻结额不重算。新动作的有限字段迁移增加 `remaining`、`filledQty` 与有效期；只读账户报告对旧字段也有回退。缺少流动性索引的旧存档从同日成交记录重建各标的/方向已用量，盘口预览在迁移写入前也读取同一回退；若旧成交已超过新共享上限，保留既有成交并阻止当天继续消耗。旧七字段请求指纹保持重试兼容，新请求包含有效期以拒绝同一 ID 的 DAY/跨日冲突。

每局新增委托上限 500、成交记录上限 1000、理由最多 300 字、最多 250 个交易日；没有截断现金账、成本批次或成交历史。一次真实引擎容量检查推进 250 日、累计 490 委托/490 成交、每笔 300 字中文理由：模拟 JSON 为 **1,098,496 字符 / 2,016,530 UTF-8 字节**。现有存储合同检查的是 JSON `length <= 2,000,000` 字符，并非 UTF-8 字节；学习笔记也占用同一工作区上限。最终全工作区写入仍由 storage 层检查和原子保存，不隐式删除历史。

## 对抗测试及实际修正

测试文件运行 37 项核心测试通过，并完成 TypeScript 类型检查及目标文件 ESLint。独立复核由 deployment_audit 只读完成：8 个场景 × 12 个种子共 96 组、每组 80 日，合计 25,422 次动作 / 11,571 条成交，现金账与资产守恒无失败；旧存档预算漏洞修复后由其独立复测通过。另核验 250 日 / 500 委托的边界，超限动作拒绝且不改变输入对象。核心回归包括：

1. 大单跨三档成交，只收一次最低佣金；1000 股申报成交 300 股，700 股余量仍冻结。
2. 同日连续 IOC 下单总量不能超过共享 300 股预算；后续无成交单不动现金。
3. 余量撤单/到期只释放冻结，不把已经买到的股票或已经卖出的股份撤回。
4. 当前日买入的部分不能当天卖出，次日只解锁早一日的批次。
5. 跨日部分成交手续费重计，但不重复扣滑点；现金账、FIFO 成本和实现/未实现盈亏一致。
6. 余额恰为零时，新日最低佣金不足会跳过重申报；两笔条件委托不会占用彼此冻结资金或制造负可用现金。
7. DAY 不追溯当天旧低点，且在下一日行情生成之前失效；旧存档条件仍跨日读取。
8. 同价先提交者优先、更高买价优先；涨停卖/跌停买方向仍可成交。
9. 停牌期间无成交与费用，DAY 到期、跨日条件保留；复牌事件可观察。
10. **审查后修正**：最初把“零股一次申报”错误套到成交片段，会拒绝合法 70 股部分成交。现仅验证提交的申报数量，撮合片段独立验证剩余股数和 T+1 库存。
11. **审查后修正**：低流动性仅有 100–300 股时，简单向下取整会把全部深度挤在第五档。改用最大余数分配，优先保留靠近最优价的深度。
12. **审查后修正**：表单清空数量或填入非法限价不会导致渲染异常；确认前校验数量、0.01 价格单位及当日范围。

13. **独立复核后修正**：deployment_audit 实际复现旧档缺少 `sessionLiquidity` 时可以在同一天再买一次 300 股，突破 300 股预算。已从当日成交记录重建索引，并让只读五档预览也计算当日既有成交；补测买入/卖出各自独立预算、旧成交超新上限以及翌日补充，既有现金/股份/成交不重算。

执行：`node --experimental-strip-types --test tests/simulator.test.ts` 与 `tsc --noEmit`。API 持久化及部署验证由主任务统一完成。

## 明确保留的真实性边界

未实现集合竞价最大成交量价格、真实秒级时间/外部投资者队列、撤单禁区、连续竞价动态有效申报价格范围（价格笼子）、完整交易所市价类型与保护限价制度、盘后交易、除权除息/分红税、新股/其他板块、真实停复牌限制、资金可取日和券商独有计费规则。没有以零税负分红制造收益，也没有把价格触及条件解释为真实必然成交。2026 年以外的交易日历继续明确标为预估。
