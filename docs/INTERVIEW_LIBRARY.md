# 语雀面经与备战工作台

本次新增 `/experience` 和 `/preparation`。历史基线以私有导入文件初始化，之后服务器每 30 分钟直接检查配置的语雀“秋招”目录及其子目录，也可手动触发。不会改写语雀文档。

## 数据与使用

- 分类、原文搜索、阶段筛选、按面经篇数/记录数排序、分类准备建议、人工精读专题与整场原文。
- 每题支持原始问法练习、AI 反馈与生成追问。反馈必须逐字引用本次回答；模型失败时保留作答，允许以同一请求 ID 重试。
- 个人答案、项目证据、自评掌握状态、到期复测和备战任务独立持久化。工作台可以读取现有笔面测安排，将岗位方向用于透明规则排序。
- 新问题按规则给出初步分类，标记待核对；已知原文复用人工归并，不把语义相似直接视为同题。支持人工修改、归并及排除过程说明。
- 分类总结为可解释的准备建议与当前分类高频题，不是推断候选人能力的自动评分。AI 生成的追问不计入真实题频。
- 知识资料随私有基线导入；普通个人资料也可作为训练参考。当前自动更新范围只覆盖秋招面经，其他知识页不会自动同步。

## 同步与一致性

1. 读取受保护的 Cookie 文件，只向固定 `https://www.yuque.com` 发送，不跟随重定向。
2. 按目录 ID 和父子关系确定秋招范围，包含嵌套目录，排除其他分支。
3. 比对稳定文档 ID、正文更新时间及标题/URL。只有变化文档下载 Markdown。
4. 保留匹配原文的记录 ID、人工归类；新增问法生成稳定内容标识。正文哈希绑定来源版本。
5. 再读目录验证完整性。一篇抓取失败、目录缺失或抓取期间目录变化，都不发布半成品。
6. 单事务以乐观版本校验发布整个快照。频次由有效原文的不同文档数计算，不做容易重复的累加。
7. 成功完整读取目录后，移出秋招范围的旧秋招文档归档。暑期、日常历史基线保留。文档归档不删除学习数据。

单实例线程门禁和 MySQL 命名锁阻止重复同步；运行中崩溃后连接关闭释放锁，下次任务可恢复。人工核对与后台同步冲突时返回 409，避免相互覆盖。

每次发布保存旧版和新版快照，可在界面恢复历史版本。恢复产生新修订，不回退训练记录；之后语雀同步仍以线上当前内容为准。合并后的题目可以查看原题作答和原题笔记。

## 私有部署

源码与生成的知识库严格分离，禁止把 Cookie、原文、题库种子、个人答案或评测产物提交 Git。

先运行 `python scripts/build_experience_seed.py --library /private/yuque-export --output /private/seed.json`。脚本验证源文件哈希，要求导出目录内已有版本化的题库报告和导出清单。该转换器面向当前已整理的基线，不是通用语雀导出解析器。

Java 环境变量：

| 变量 | 作用 |
| --- | --- |
| `EXPERIENCE_OWNER_ID` | 数据所属账号的 `user_id`，默认 0 不启用 |
| `YUQUE_BOOK` | `账号路径/知识库路径` |
| `YUQUE_AUTUMN_DOC_ID` | 秋招目录的稳定文档 ID |
| `YUQUE_COOKIE_FILE` | 服务账号可读的受保护凭据文件 |
| `EXPERIENCE_SEED_FILE` | 私有初始化 JSON；仅首次无库时导入 |
| `YUQUE_SYNC_INTERVAL_MS` | 检查间隔，默认 1800000 |
| `EXPERIENCE_AI_PROVIDER` / `EXPERIENCE_AI_MODEL` | 复用现有 Python gRPC 模型调用 |

Cookie 失效后同步状态为失败，已有数据可继续使用。将新 Cookie 原子替换到原文件后重试即可，服务每次请求重新读取文件。不会把凭据下发浏览器。

所有 API 从登录身份确定 user_id，不接受客户端指定资料所有者。未接入的账号只显示空状态；无法读取所属账号的原文、版本或练习。

## 当前边界

- Cookie 页面数据与 Markdown 导出接口属于网页集成，可能随语雀变化；完整性校验失败时停止发布，不把失败误当删除。
- 新问法的细粒度语义合并需要核对。规则分类与岗位排序不是概率模型。
- 历史专题是导入快照。源文档变化后，训练跳过无法追溯的旧行，并提示用户。
- 不包含录音转写、音频说话人识别或 SQL/故障实验执行器。
- 数据量按个人知识库设计，使用 MySQL 版本化 JSON 快照；规模扩大后可迁移为规范化题目/来源表。当前保留版本历史，需按实际增长制定保留策略。

## 发布验证

发布前执行 Java 全量测试、前端全量测试与生产构建；macOS 上 Java 测试使用规范临时目录 `-DargLine=-Djava.io.tmpdir=/private/tmp`，避免原有路径策略测试受到 `/var` 符号链接影响。

对抗检查覆盖：重复同步、重复问法、来源归档、目录变化/失败不发布、跨账号访问、来源链接限制、合并后历史可访问、AI 失败保留回答，以及阶段筛选重新计算频次。生产发布需保留旧 JAR、前端和环境文件，完成健康、同步幂等和登录态回归后结束。
